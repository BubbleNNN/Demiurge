## Rendering

Images use alpha cutouts; static illustrations remain still, and authored sprite frames use Canvas 2D. Missing facial images fall back to the neutral image and are described honestly in the workbench.

Live2D loads vendor Core from local public/vendor and uses pixi-live2d-display's Cubism 4 adapter. Pixi's unsafe-eval replacement permits rendering without allowing general JavaScript eval in CSP. Manifest motions/expressions are mapped to normalized chat actions; unsupported expressions retain/reset model defaults. Imported sound references are removed so model sounds cannot unexpectedly play over configured TTS.

VRM uses Three GLTFLoader and VRMLoaderPlugin. It normalizes VRM 0 orientation, applies basic skeletal movement, drives lookAt, expressions, blinking and the aa mouth channel. These are procedural motions, not learned animation or motion capture. Model-specific expressions and bones determine available behavior.

The speech response is played locally through an AudioContext analyser. RMS amplitude is a simple mouth-opening signal, not phoneme alignment. API-to-audio behavior requires a working user-provided provider.
