# Mori 0.3.3 · 画风参考与小尺寸预览

0.3.2 已支持在动作制作前修正候选。0.3.3 进一步增加可选的画风图片输入，并让候选可以按较小尺寸比较。目标是帮助用户表达具体的画法，提前发现桌面显示时不清晰的细节。

## 独立画风参考

自动制作的「外观与动作的细节」中新增单图输入。角色参考仍负责人物身份、服装和配色；画风图片只提供线条、上色方式、材质和细节处理的参考。接受 PNG、JPEG、WebP，单张最多 8 MiB，边长最多 8192 像素；导入和发送前检查格式及解码。

请求将角色原图与画风图按不同用途明确声明。画风图放在角色原图之后；修图时先放要修正的候选，再放角色原图与画风图。后续动作使用已选定的候选和角色原图，不再次用画风图重新设计角色。

画风参考作为任务的独立图片快照保存，任务本身只记录名称、ID 和图片摘要。重开、候选修图、已完成任务的修正版与完整工作区备份都保留这张快照。图片丢失或与记录不符时，会在新请求前停止；已有返回图片的本机恢复不依赖它。查看快照不会调用模型。

原作画风以角色原始画法为准，混合画风任务也不会把独立画风图传入原作阶段。为已有确认基准补动作不接收新的画风图。没有身份参考时仍不能制作，文字和画风参考不能取代角色原图。

增加一张参考图不会增加请求次数，但不能据此认为费用不变，实际费用取决于服务的计费方式。

## 小尺寸核对

候选放大面板新增「预览高度」，可以选择适应区域、96、160 或 240 像素。小尺寸模式保持图片比例，原图与候选、修正前与修正后都可以并排比较；透明格、深色和浅色背景继续可用。像素画保持硬边显示。

这是显示尺寸控制，不修改生成分辨率、角色选择、桌宠大小或任务状态，也不发送任何图像请求。实际清晰度与角色在透明画布中的占比仍由源图片决定。

## 开源借鉴与能力边界

本轮读取 Diffusers / IP-Adapter、ComfyUI IPAdapter Plus 和 sprite-gen 的文档或代码，借鉴参考用途分开、先确定母图再生成动作的组织方式。来源、许可证与取舍见 [调研记录](PET_STYLE_REFERENCE_RESEARCH_2026_10_23.md)。没有复制上游代码、美术或模型权重。

Mori 当前使用多图编辑与提示词用途声明，没有接入 adapter 层、风格权重或自动审美判断。模型可能仍把画风示例中的内容带入结果，因此必须核对角色身份与服装，不能把结构化输入当作画质或身份稳定性的保证。

## 验证

TypeScript 与生产构建通过，293 项 Node 测试全部通过。服务测试实际读取 multipart 中的图片字节，验证四张身份原图与第五张画风图的顺序、用途与独立来源记录。任务测试覆盖缺失和篡改阻断、保存失败、修正版复制，以及完整工作区备份恢复。

新增真实 Electron 验收使用 7 个固定图像响应，验证：

- 没有图像配置也可本机导入、取消和移除画风图；角色参考列表保持原样。
- 原作阶段与已有基准补动作不传画风图，其他画风的基准与修图确实传入保存的原始字节。
- 更换新任务的草稿后，旧任务与修图仍使用原快照；延迟返回的旧任务图片不会覆盖当前任务。
- 重载恢复参考图，动作只使用明确选定的基准与角色原图。
- 两侧图片实际高度分别为 96、160、240 界面像素，比例保持；预览不增加请求或改变候选选择，窄窗口没有水平溢出。

原有自动制作、候选修图和成品修正版的原生回归也已通过。

测试使用隔离工作区、固定 PNG 响应和原生 Electron 窗口，不调用收费生成服务。报告与截图见 [artifacts/mori-0.3.3](../artifacts/mori-0.3.3/)。本轮没有生成新的真实角色美术，固定测试图片只用于检验输入、保存与交互行为。
