# Anime Codex → Mori：角色动画制作与桌宠运行迁移

目标仓库：`Documents/GitHub/Mori`。版本：0.3.8。来源为本机 Anime Codex 0.19.3 工作树；其中包含尚未提交的实现，不能只用其旧 Git HEAD 复现。本次在 Mori 现有未提交工作之上增量适配，没有覆盖旧工作区、角色存档、模型配置或已生成图片。

## 角色到动画

继续使用 Mori 的角色资料检索、来源核对、身份参考图、可选画风参考图、候选审核、动作生成、透明背景/切帧 QA、单动作修正及最终启用流程。移植 Anime Codex 的方向动作与动作过渡设计，适配为 Mori 原生的动作组与图集，不启动第二套 Claude/Codex 执行后端。

入口：角色工作室 → 外观与动作 → 自动制作多画风桌宠 → **完整桌宠动作包**。仍可逐项选择，界面会显示请求数量，点击开始才调用配置的图像服务。新任务保存 `transitionVersion:2`，已有任务未声明版本时仍按旧流程解析。

新增：独立向左/右/前/后跑动，被拎起，倾听，办公；睡眠升级为躺下/熟睡/起身。生活活动与方向动作采用八帧，组成进入、循环、退出三段；活动之间先退出再进入，不靠淡入淡出伪装动作。拖动直接中断当前动作，松手再恢复。保持角色原有服饰朝向，不把镜像图片当作另一方向。

播放、预览、存档验证、模型可选动作、角色包导入导出均识别新动作。旧版四帧睡眠图仍可打包/续做。旧 VRM 不会被错误标为具有新方向跑动能力。已有素材不会自动长出新动作，未制作的动作保持能力受限。

## 桌宠运行

Mori 已有的性格/需求时钟、活动持续时间、邀请退避和共同经历继续使用。修复独立桌宠「只显示邀请就记作被忽略」的问题：现在可接受/拒绝、打开猜手等小游戏，结果才记入经历；邀请超时不再因自身显示而永久暂停。

桌宠悬停工具栏新增 **⌖ 探索桌面**、**♡ 一起玩** 和活动中的停止入口。设置 → 桌面陪伴 → 自主探索桌面与寻找活动位置，可独立关闭。角色读书/办公时尝试找窗口边缘；邀请玩耍时可先找露出的图标，接受后再藏起来。成功后冷却 8 分钟，失败 30 秒后可再找；手动探索不受冷却限制。移动有速度上限、到达前复查；停留最多 90 秒，藏身最多 45 秒。聊天、拖动、关闭动态、切换角色会中断自主活动。

窗口感知只返回几何信息。macOS Finder 图标识别只返回位置与尺寸，不读取文件内容/名称；系统若要求自动化授权，应用会显示说明。窗口遮挡、负坐标显示器、目标移动/消失均处理。原生 helper 随平台编译并纳入安装包白名单，源文件位于 `electron/native/desktop-bounds.swift`。

## 验证与边界

- `npm test`：340 项测试通过（包括旧制作任务兼容、新动作打包和桌面坐标测试）。
- `electron scripts/test-pet-activities-desktop.cjs`：真实 Electron UI/IPC/PNG codec，模拟图像响应，制作→预览过渡→审核→启用桌宠通过，0 付费请求。
- `npm run test:migration`：隔离存档，桌面感知、无目标反馈、移动到测试位置及桌宠小游戏通过，0 模型请求。位置测试使用确定性几何数据，不等同真实桌面的长期视觉验收。
- `node scripts/test-packaged-desktop.cjs`：0.3.8 安装包真实启动、原生桌面接口、小游戏、存档重载、依赖/资源审计通过。

此迁移不等于新角色素材已经生成并获视觉验收。已有角色需要在制作页补齐新动作；图标遮挡沿用矩形近似，尚无攀爬、坐姿、像素轮廓探头动画。macOS 以外平台可继续制作和陪伴，但没有本轮的原生窗口/Finder 感知。Anime Codex 的任务分发、Claude 翻译和多角色来访编排未作为这次动画/单桌宠迁移的一部分搬入 Mori。

源代码来源许可保留于 `docs/licenses/anime-codex-MIT.txt`，安装包亦包含该许可。未复制 Anime Codex 角色图片或用户聊天历史。

## 0.3.9 制作流程对齐（2026-11-07）

对照本机 anime-codex 的 `shared/pet-production.cjs`、
`electron/character-studio.cjs`、`electron/pet-artifacts.cjs` 和 `src/PetSprite.jsx`，
发现先前只迁移了动作名称与播放支持，没有完整迁移素材制作要求。

新建任务写入 `transitionVersion: 3`；旧任务保留旧版布局，续跑与修正不重解释旧图。

| 环节 | 旧 Mori 流程 | 新流程 |
| --- | --- | --- |
| 默认素材 | chibi、六种基本表情手势，无跑步 | 清爽贴纸、完整二十种动作，四向跑步均选中 |
| 生活与跑步 | 八帧挤入进入、循环、退出；跑步三帧 | 十二帧：进入四帧、独立循环四帧、退出四帧 |
| 姿势要求 | 生活活动站立，禁止桌椅 | 坐着阅读、接书、低桌吃点心、坐着打游戏、桌前办公、蜷缩睡觉再起身 |
| 连续性参考 | 单张基准加身份原图 | 上述参考加至多两张同风格、同基准的已完成动作图；不增加生成请求 |
| 对齐 | 逐帧按脚部重心横移 | 每组只根据第一帧基准配准，保留脚步、重心和跳跃变化 |
| 清晰度 | 图集超限时逐级缩小 | 插画帧只做整像素平移和透明填充，保留 RGBA 样本；超限明确失败，素材仍已保存 |
| 检查 | 整张图有变化即可 | 分别检查进入、循环、退出；跑步循环必须四个可见不同阶段，蜷缩不会因高度降低被误拒 |

Anime Codex 把不同动作按行放进多张 4×4 图；Mori 保留按动作暂停、续跑、单独修正的能力，
每组用一张 1024×1024、4×3 的十二格图承载同样的三个四帧段。
这属于动作制作要求与时序的对齐，不是图集文件格式完全相同。
非像素新流程不再对插画样本做双线性重采样；像素画保持自身像素显示约束。
完整默认配置是 177 帧；常规表情改选八帧时会更多。
图集最大 8192 边长、32M 像素、8 MiB 文件；与前端解码预算一致，不无限扩大内存。

用户重跑：角色工作室 → 外观与动作 → 自动制作多画风桌宠 → 新建制作。
保留默认清爽贴纸、完整动作包、自然气质和先审基准图；确认基准之后再继续。
成品预览四个跑步方向，以及睡觉到读书、读书到跑步等组合，然后审核启用。
旧版成品缺少的动作不会因为升级应用自动出现；请不要用旧任务的“继续”替代新建任务。

验证：单元测试涵盖旧版兼容、断点续跑参考、跑步半周期、睡姿比例、横向抖动、原像素保留；
Electron 测试涵盖真实图片编解码、默认配置、请求内容、审核与桌宠进入/循环/退出播放；
完整尺寸合成素材验证二十动作、177 帧打包及前端解码预算。
所有测试为本地合成素材，零真实图像生成请求；这不构成新角色成品美术质量验收。
Anime Codex 现有芙宁娜素材还包含专门修过的图片、裁切和偏移，自动生成不能保证逐像素复现该成品。
