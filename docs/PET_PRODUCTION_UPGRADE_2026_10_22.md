# Mori 自动桌宠制作改进 · 2026-10-22

本轮先查 GitHub 并阅读项目 README、动作规范和校验代码，再修改 Mori。下列项目只作为实现思路来源；没有复制第三方角色图片、安装外部 skill 或运行第三方生成工具。

## 已落地

1. **先看角色图再做动作**：制作界面默认在每张新基准完成后暂停，展示基准预览。用户可以继续动作，或结束任务保留素材并重新调整要求。预览只读，不会安装未核对角色图、改变当前角色或触发请求。这个停靠点是界面的制作节奏控制，不是服务端的强制审批机制；用户也可取消勾选连续制作。
2. **外观要求**：最多 600 字的可编辑要求进入基准生成请求，随任务保存；每个动作继续使用该基准和原始参考字节。要求不能取代角色身份、服装及所选画风约束。已有已确认基准补动作时不重新修改外观。
3. **四帧 / 八帧**：四帧保持 1024×1024、2×2；八帧请求 1536×1024、4×2，每格 384×512，针对眨眼、说话、招手、点头、摇头、小跳、休息分别写出八个姿势。四种表情仍只生成四帧。模型必须支持横向请求；不支持时按现有失败流程停止，不自动补发。
4. **动作气质与时序**：自然、轻柔、活泼同时影响动作提示和播放节奏。轻柔时长乘 1.25、活泼乘 0.85；不同动作使用独立时长。休息只循环闭眼部分，口型显式对应闭嘴、小口型和大口型。
5. **任务恢复**：帧数、动作气质、外观要求持久保存，恢复时使用任务自身参数；没有新增参数的旧任务按四帧、自然节奏继续。八帧技术检查要求至少六张不同位图，不接受错误布局；最终仍需人工核对解剖和衔接。
6. **画风可读性**：画风卡直接展示比例、材质等差别；基准提示强调桌面小尺寸下的轮廓、五官、色块及饰物可读性。保留现有七套画风，未重新启用历史移除的路线，也未自动重做已有美术。

7. **大图集与任务切换**：四列排版超限时自动调整列数，保留各帧原始尺寸和索引；仍执行 8192 边长、16 Mi 像素和 8 MiB 上限。快速切换任务时清空旧预览，并使旧异步响应失效，避免看着旧形象继续新任务。

同样的动作数，四帧与八帧请求次数相同，但图片面积、服务定价和失败率可能不同，不能称费用相同。八帧增加姿势数量，并没有提高每张姿势的原始分辨率。现有图集尺寸/文件上限仍然执行，超限不会偷偷降画质。

## 下一阶段优先级（未实现）

后续同日 0.3.0 已实现第 1 项的多候选与文字驱动形象修正版，以及第 2 项的单动作修正版；不包含逐像素蒙版编辑。当前说明见 [0.3.0 完善记录](MORI_0_3_RELEASE.md) 与 [自动制作使用文档](AUTOMATIC_PET_PRODUCTION.md)。以下保留原阶段的计划记录。

1. **基准多候选和局部修改**：同一角色、同一画风并排比较候选；选定后再扩展动作。允许只修脸、手或服饰，保存修改前后版本。
2. **单动作替换**：目前失败阶段可重试，但已完成且视觉不满意的某一动作还不能在整套成品里独立重绘替换；需要管理候选版本和重新核对状态。
3. **独立画风参考**：角色参考负责身份，画风参考负责材质与造型；应分别上传、解释用途和保存来源，不能仅堆叠风格名称。
4. **素材制作路线分开**：像素、逐帧插画、Live2D 分层绑定、真实 3D 骨骼各有不同输入和验收条件。视频/专用动画生成值得研究，但必须新增服务适配、任务恢复、透明处理和视觉评测。
5. **真实画质实验**：固定昔涟的参考图与一个新角色，用少量基准及招手/小跳对照四帧和八帧，记录身份、肢体、接缝、清晰度与成本；结果不佳时保留四帧或调整制作路线。
