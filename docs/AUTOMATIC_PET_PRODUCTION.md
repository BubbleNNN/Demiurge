# 自动制作 2D 桌宠

> 0.3.0 更新：支持每画风 1–3 张角色候选、选择后制作动作，以及独立的单动作/角色形象修正版。外观要求、三档动作气质、四帧和实验性八帧均随任务保存。下文四格姿势表描述默认四帧模式；八帧的姿势和质量边界见 [制作改进记录](PET_PRODUCTION_UPGRADE_2026_10_22.md)，完整使用步骤见 [使用指南](MORI_USER_GUIDE.md)。图集会调整排版以保留原始分辨率；仍超出尺寸或文件上限时停止，不自动降低清晰度。

本轮集中调试「外观动作」模块：从角色参考原图开始，为多种画风生成各自的角色图、姿势帧、表情和动画图集，再在现有桌宠运行时播放。入口是「外观工作台 → 自动制作多画风桌宠」。

## 使用方式

1. 保存角色档案，添加并核对参考原图。最多四张，第一张决定主体形态、服装和轮廓。没有原图时可以自动收集；只有社区索引中名字匹配的角色立绘会被自动采用，其他结果仍留在候选区，等待确认。网页链接和外貌文字不能替代图片输入。
2. 在「连接设置 → 图像」中配置图像 Key、基础地址和模型 ID。当前适配 multipart `/images/edits`，需要服务实际支持多图参考编辑与透明 PNG。Claude 聊天 Key 和聊天模型不会自动变成图像服务配置。
3. 多选画风和动作，设置每种画风的候选数、动作帧数、动作气质和外观要求，查看预计请求数量。默认一张 Q 版角色图及眨眼、说话、招手、点头、休息、四种表情，共七次图像请求。已有经过确认且对应当前原图的静态角色图也可直接补动作，省去基准图请求。
4. 点击开始后按阶段执行。单候选默认在角色图完成后停下供预览，可关闭此选项连续制作；多候选始终在本画风的所有角色图完成后等待选择。点击某张候选的「选择并继续」才以它为基准制作动作。每个阶段保存原始输出，每种画风完成后保存为待核对成品。可以在当前请求结束后暂停，重新打开原任务继续。
5. 在结果区对照原图试播并逐帧查看，核对肢体、身份和动作衔接后再启用。核对绑定当前图片和时序，修正版需要重新核对。之后可打开透明桌宠，或导出含图片、时序和角色资料的角色包。

每个任务按画风执行：**独立角色候选 → 选择本画风基准 → 所选动作姿势图 → 本机检查与图集合成 → 逐帧核对后启用**。动作生成同时发送选定的本画风基准和全部原始参考字节。完整请求提示、来源摘要和返回图片留在本机任务文件中。

## 画风、动作与请求数量

支持原作画风、精绘、Q 版、清爽贴纸、飞天小女警、像素、8-bit 和低多边形 3D 八种绘画路线。飞天小女警路线使用超大椭圆眼、短小身体、粗黑描边与纯色平涂，与普通 Q 版分开。原作画风使用真实原图同时约束身份和绘画方式，重新绘制姿势，不直接使用原图。这里的 3D 仍是相应视觉风格的 2D 图片；本功能不创建可旋转网格、骨骼或 Live2D 模型。每种路线使用已有的独立材质、比例与造型提示，实际区别取决于服务输出，不能仅凭提示词宣称画质达标。

| 动作组   | 默认姿势内容                     | 运行方式                 |
| -------- | ---------------------------- | ------------------------ |
| 眨眼     | 睁眼、半闭、闭眼、重睁       | 待机时有限播放           |
| 说话     | 闭嘴与三种说话口型           | 对白期间循环，结束闭嘴   |
| 招手     | 放松、抬手、挥手、放下       | 完整播放后回到基准待机   |
| 点头     | 直视、低头、进一步低头、返回 | 用于回应和直接触摸       |
| 摇头     | 直视、转左、转右、返回       | 只转动头颈               |
| 小跳     | 待机、屈膝、离地、落地       | 保留真实姿势中的离地距离 |
| 休息     | 睁眼、困倦、闭眼、轻微呼吸   | 两个休息姿势循环         |
| 四种表情 | 开心、思考、低落、惊讶       | 对应情绪静态帧           |
| 读书 | 固定八帧：拿书、阅读翻页、合书收好 | 进入后循环，约一分钟后退出，可手动停止 |
| 玩掌机 | 固定八帧：拿出、按键游玩、放下收好 | 进入后循环，约一分钟后退出，可手动停止 |

新建任务的图像请求数 = **画风数 ×（候选数 + 动作组数）**。单候选、全选十组动作时每画风十一次；八种画风全选为八十八次。两张候选和默认六组动作为每画风八次。已有确认角色图补动作只计动作请求。候选未选定时不会提交动作请求；界面的「选择并继续」会在保存选择后启动后续动作。四种表情始终在一次四格图请求中产生。合成、预览、核对、导出和打开桌宠不请求图像模型。四帧和八帧的请求数量相同，图像面积与收费可能不同；明确重试会新增请求。

原有八组动作全部生成时，四帧模式为三十三帧，八帧模式为六十一帧（含基准与四种表情）。新生活活动每组固定增加八张源姿势，进入/退出复用这些帧；全选十组时分别共四十九帧或七十七帧。循环和有限动作复用这些帧。逻辑画布默认 384×512；像素路线使用最近邻，其他路线平滑缩放。不会声称高分辨率模型输出满足严格的 8-bit 分辨率或十六色调色板。

## 修正成品

已完成任务的成品下方提供「修正范围」与「修正要求」。可选择一个已生成动作，或「修正角色形象并重做动作」。填写具体问题，例如“招手时保持左臂不动，右手五指分明，挥手幅度小一点”，再点击「制作修正版」。

- **单动作修正**：只提交该动作的一次图像请求，继续使用原选定角色图及原始参考，其他动作逐字节复用，再本机合成新图集。原任务、原成品和当前已启用桌宠保留。
- **角色形象修正**：以原选定角色图和原始参考做图像编辑，随后以新角色图重新生成此画风全部动作；请求数为 1 + 动作组数。没有逐像素蒙版，文字修正不能保证其余区域完全不变。

修正版有独立任务、修正说明和来源关联。完成后仍为待核对成品，不能继承旧图片的审核。缺少原任务素材、原图或图像配置改变时停止并说明原因；同一角色同一画风已有未完成任务时需先继续或结束它。任务素材也包含在完整工作区备份中。

## 检查与失败恢复

技术检查包括真实 PNG 解码、尺寸与文件上限、透明背景、边缘留白、四格完整裁切、四帧非完全相同和同一动作内的主体尺寸范围。每个动作整体使用固定平移和缩放，参考首个待机姿势对齐；不逐帧重新居中，因此小跳不会被对齐逻辑抵消。图集大于八 MiB 或超过尺寸上限时停止，提示减少动作或拆分角色包；不自动降低分辨率。

这些检查不能证明人物相似度、解剖正确、四格中每个动作语义正确或时间连续性。四个关键姿势可能仍显得生硬，模型也可能错画格子。最终视觉核对保留在人可以查看的原图对照和实际动画试播中。后续增加更密集原画、局部修复或动画服务适配时，应保持同样的角色身份与完成阶段恢复机制。

| 状态                     | 操作                   | 是否请求模型                   |
| ------------------------ | ---------------------- | ------------------------------ |
| 等待 / 已暂停            | 继续自动制作未完成阶段 | 下一个角色图或动作阶段会请求   |
| 已返回素材但本机保存失败 | 仅恢复本机保存         | 否；恢复完仍需单独点击继续     |
| 返回图未通过技术检查     | 明确重新生成当前阶段   | 是；保留被拒原图及其他完成阶段 |
| 请求被中断、没有输出     | 明确重试当前阶段       | 是；不会自动重复不确定请求     |
| 图集整理失败             | 重新整理图集           | 否                             |
| 已完成                   | 试播、核对、启用或导出 | 否                             |

任务和素材保存在应用数据目录的 `pet-jobs/`。本机任务元数据不含 Key；原始图片单独保存。启动前先写入任务阶段标记；输出返回后先保留图片再更新检查点。重启时有本机输出的阶段恢复为待保存，没有输出的中断阶段需要明确重试。不可恢复地退出进程之前若素材还未成功落盘，不能保证回收当次返回图；这种情况下不会自动付费补发。

原图或图像地址、模型、输入保真度发生变化时，原任务停止继续，避免把不同输入混在一套动作中。需要恢复原图/配置，或结束旧任务后新建。已生成的素材保留。密钥轮换不改变图像任务身份。

## 实现与验证边界

- `src/features/appearance/PetProductionStudio.tsx`：选择、任务控制、原图对照、试播和启用。
- `electron/pet-pipeline.cjs`：持久任务、单阶段执行、本机保存恢复和候选安装。
- `electron/pet-frames.cjs`：透明帧检查、动作整体注册、图集和时序。
- `electron/services.cjs` 与 `shared/pet-motions.json`：原图编辑请求及具体关键姿势约束。
- `tests/pet-pipeline.test.cjs`：阶段恢复、技术检查、原图变化与并发任务控制。
- `scripts/test-pet-production-desktop.cjs`：隔离数据的原生界面、真实 PNG 编解码、IPC、保存恢复、预览、导出和透明桌宠窗口。

原生回归的图片响应是本地测试素材，不调用付费模型，也不证明实际模型画质。真实服务仍需用已配置的模型产生第一套角色，再人工核对画风、还原度和动作衔接。生成服务可能无法稳定保持人物或精确布局，这也是必须把原始输出保留为可审阅素材的原因。[OpenAI 图像生成指南](https://developers.openai.com/api/docs/guides/image-generation)。
