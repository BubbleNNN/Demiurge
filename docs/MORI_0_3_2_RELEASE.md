# Mori 0.3.2 · 先修角色图，再制作动作

上一版已经支持候选对比和成品修正，但不满意候选时只能重建任务，或等动作完成后再修正整套形象。0.3.2 在候选阶段增加「修正这张」，让用户先调整脸部、比例、服饰或边缘，再选择用于动作制作的角色图。

## 使用方式

1. 在自动制作中等当前画风的角色候选完成，点击要调整的一张的「修正这张」。单候选暂停和多候选选择都支持；动作已经开始的画风不再开放这个入口。
2. 填写最多 600 字的具体修改要求，再提交。界面明确显示预计一次图像编辑请求。
3. 新图保存为另一张候选，原候选保留。面板默认把修正前与修正后的候选并排显示，也可以切换为角色原始参考，继续放大或检查透明边缘。
4. 核对后点击喜欢的一张的「用这张继续」，才开始动作制作。即使关闭了原有的「角色图完成后暂停」，候选修图仍会强制等待选择。

每画风最多保留六次候选修图记录，每任务最多十二次。可以对已完成的修正图继续提出要求。失败记录也计入上限；明确重试已有失败记录不新增记录。

## 保存与请求边界

候选修图独立于原有制作步骤，已有角色图、动作文件与步骤索引保持原样。修图使用明确选中的候选原始 PNG，并附上角色参考图；动作生成沿用最后明确选中的候选。原始候选与新候选都不自动成为当前桌宠。

发送请求前先保存来源图片与任务状态。如果来源或状态保存失败，不发送请求。收到图片后先保存原始结果，再检查技术格式并完成记录；保存出错时保留可恢复输出，提供「仅恢复本机保存」，不会再次调用模型，也不要求可用的图像密钥。中断且没有输出时显示需要处理，重开任务不会自动重试。

失败或中断的修图需要明确重试，重试预计新增一次请求；也可以直接选择原候选继续。已经开始动作后，历史修图保留但不能再改变本任务的基准。取消的任务不会因为恢复中断记录而重新开始。

## 验证范围

TypeScript 与生产构建通过，**275 项 Node 回归全部通过**。原有自动制作与成品修正的真实 Electron 回归通过；新增候选修图窗口验收使用 9 个固定图像响应、0 次收费请求，验证：

- 单候选、多候选均能直接修图，每次只发送一次图像编辑；忙碌期间的重复点击不新增请求。
- 修图输入与选中候选原始 PNG 字节一致，原候选及步骤索引保留；后续动作实际使用明确选中的修正版。
- 关闭普通暂停选项后仍停在选择阶段；重载窗口不会自动生成动作。
- 新旧图片放大、切换参考与候选不改变任务选择；900 像素窗口没有水平溢出。
- 注入图片保存错误后，移除图像密钥并令凭据读取失败，本机恢复仍成功，凭据读取次数与新增图像请求数均为零。
- 角色档案、聊天、记忆保留，生成的成品不会自动启用。

macOS arm64 独立应用包验收通过：从临时目录启动真实打包程序，检查首启、本地陪伴、透明桌宠、Live2D 运行库、重载保存与包内依赖；未使用开发服务器或正式用户数据。应用位于 `release/Mori-0.3.2-macOS-arm64/Mori.app`，ZIP 位于同级目录。当前仍为未签名、未公证的本机使用包。

验证报告、测试日志和真实 Electron 窗口截图保存在 [artifacts/mori-0.3.2](../artifacts/mori-0.3.2/)。原生测试使用隔离工作区与固定 PNG 响应，覆盖真实界面、IPC、磁盘保存和发送给图像接口的字节；不调用收费服务，不修改日常角色、聊天或密钥。

本轮改进的是形象迭代流程，没有生成新的真实角色美术，也没有引入自动审美判断。参考图编辑仍可能改变未指定的区域，最终身份、肢体和动作衔接需要人工核对。
