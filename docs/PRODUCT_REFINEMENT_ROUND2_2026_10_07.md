## 具体变化

| 范围 | 本轮开始时 | 本轮完成后 |
| --- | --- | --- |
| 角色试聊 | 每次只发送当前一句，无法验证连续聊天是否保持人设 | 原生进程按窗口保存独立上下文，每段最多 8 轮；支持追问、重新开始、取消和失败重试 |
| 人设核对 | 只能阅读单条回复，没有整理问题的入口 | 逐条人工标记「贴合角色／需要调整」，选择身份、事实、语气、关系、动作问题，并填写备注；可以复制摘要，或复制后进入档案编辑 |
| 上下文隔离 | 单次试聊隔离，尚无多轮会话生命周期 | 不加载正式聊天或个人记忆；仅成功回复进入当前试聊；角色资料变化或闲置 30 分钟后重置；关闭或重开后，旧请求不能加入新会话 |
| 新角色准备 | 展示五项状态，需要用户自行决定下一步 | 按已有候选、原图、可用外观、语气、台词和动作推荐具体入口；完整导入的角色包不因缺少原始参考图被当作未完成 |
| 外观筛选 | 设置页与其他入口的外观筛选条件不完全相同 | 共用已确认、属于当前角色且参考仍有效的外观筛选；参考图操作增加同步提交锁 |
| 试聊布局 | 沿用单条回复区域，多条记录会挤出发送按钮 | 记录区独立滚动，角色与输入区保持可见；900 和 1400 CSS 像素宽的原生窗口中，发送按钮无需滚动弹窗即可使用 |

## 使用方式

1. 打开「角色档案 → 角色试聊」，从日常问候开始，再追问上一句。也可以选择身份、未知设定、关系边界等预设场景。
2. 对不符合角色的回复点击「需要调整」，选择问题并记下原因。标记完全由用户判断，不是模型自动评分。
3. 点击「复制摘要并调整设定」。成功复制后才打开编辑器，摘要中保留问题、回复摘录和人工备注；档案不会被自动重写。
4. 保存设定后重新试聊。每段最多 8 轮，可以主动开始新段；失败和取消的输入保留在输入框，便于修改后重试。

摘要最多复制最近 8 轮的摘录，单条回复仍可以完整复制。试聊记录与标记仅用于当前弹窗，关闭后清除。每次发送使用已配置的聊天 API；主动点击「听一听」沿用现有语音设置，可能调用已配置的 TTS。

## 实现与能力边界

- `electron/persona-sessions.cjs` 管理会话令牌、窗口归属、提交代次、闲置期限和角色资料摘要。只有请求成功且仍属于当前会话时才提交；不把试聊或模型建议的记忆写进存档。
- 角色设定始终从已保存的档案读取。角色名字、作品、语气、知识、来源、关系与行为等变化会使旧上下文失效；改图片或主题配色不影响对话身份。
- 沿用正式对话的上下文长度预算（6,000 / 12,000 / 24,000 字符）和原有资料约束、动作能力检查。8 轮是试聊长度上限；长消息仍可能受上下文预算裁剪，不能宣称所有历史无限保留。
- 人工反馈只帮助发现问题和编辑设定，未实现自动训练、模型裁判或 OOC 自动修复。本轮没有用实际供应商评测角色相似度，测试通过不代表模型永不跑偏。
- 新角色接续仍依赖可靠来源和可用素材。已有原图可直接启用静态外观；没有素材时，不会声称已生成新动画。
- 参考图同步锁避免组件同一时刻重复发起操作，不是跨进程下载调度或持久任务队列。
